# 학급 진도/기록 관리 웹앱 설계

## 배경 및 목적

중고등 교과담임 교사가 여러 학급의 수업 진도를 확인하고, 학급별 특이사항·학생 기록(출결, 칭찬/포인트, 과제 제출 등)을 날짜와 함께 쉽게 저장할 수 있는 웹앱.

중앙 서버/DB 없이, 각 교사의 로컬 기기(브라우저)에서 개별적으로 데이터를 관리한다. 다른 교사도 별도 설치나 계정 가입 없이 웹에 접속해 바로 쓸 수 있어야 한다.

## 참고 조사

하이클래스, TeacherKit, iDoceo, Additio, Smart Seat 등 기존 학급관리 앱 조사. 공통적으로 출결 관리, 누가기록, 칭찬/포인트, 좌석배치, 학생 리포트 기능을 제공함을 확인. 이 중 학급당 다수 반을 담당하는 교과담임 시나리오에 맞게 필요한 기능을 선별함.

## 범위

- 대상: 중고등 교과담임 교사 (여러 반, 한 과목)
- 1차 버전 포함 기능: 진도표 체크, 학생 명렬표, 자리배치표, 출결 관리, 칭찬/포인트 스티커, 특이사항·과제제출 등 학생 기록, 백업/복원
- 1차 버전 제외: 사진 첨부, 랜덤 학생 뽑기, PDF 인쇄 내보내기, 통계 대시보드 (추후 확장 후보)

## 아키텍처

- React + Vite로 구성한 정적 웹앱. 별도 백엔드 서버 없음.
- 정적 빌드 결과물을 GitHub Pages 등 아무 정적 호스팅에 배포하거나, 로컬 파일로도 열람 가능하게 구성.
- 데이터는 브라우저 IndexedDB에 저장 (Dexie.js 사용). 기기/브라우저를 벗어나지 않음.
- 데이터 유실 방지를 위해 전체 데이터를 JSON 파일로 내보내기/불러오기 하는 백업 기능을 필수로 제공한다 (중앙 DB가 없으므로 기기 변경이나 브라우저 데이터 삭제 시 유일한 복구 수단).

## 데이터 모델 (Dexie 테이블)

- `classes`: 반 정보 — id, 반 이름(예: "1학년 3반")
- `students`: 학생 — id, classId, 번호, 이름, 좌석 위치(row, col)
- `curriculum`: 공통 진도표 항목 — id, 순서, 단원명, 차시명 (모든 반이 공유하는 진도 목록)
- `progress`: 반별 진도 체크 — id, classId, curriculumItemId, 완료 여부, 체크한 날짜
- `attendance`: 출결 기록 — id, classId, studentId, 날짜, 상태(출석/결석/지각/조퇴), 비고
- `stickers`: 칭찬/포인트 기록 — id, classId, studentId, 날짜, 점수, 사유
- `records`: 특이사항/과제제출/기타 기록 — id, classId, studentId, 날짜, 유형(드롭박스: 특이사항/과제제출/기타), 내용

진도표(`curriculum`)는 과목 공통으로 한 번만 입력하고, 각 반은 `progress` 테이블에서 반별로 독립적인 체크 상태를 가진다.

## 화면 구성

### 설정 페이지
- 반 생성/이름 수정/삭제
- 학생 명단 입력 (수동 입력 및 붙여넣기 지원)
- 공통 진도표 입력 (순서, 단원명, 차시명)
- 백업: 전체 데이터 내보내기(JSON 다운로드) / 불러오기(JSON 업로드)

### 학급 탭 (반 선택 후 하위 탭 4개)
1. **진도 체크**: 공통 진도표 목록을 순서대로 표시, 체크박스로 완료 표시. 체크 시 오늘 날짜가 자동 기록되며 수정 가능.
2. **명렬표**: 번호/이름 테이블, 인라인 편집 가능.
3. **자리배치표**: 격자 위에 학생 카드를 드래그앤드롭으로 배치. 배치 결과는 학생의 seat(row, col)에 저장.
4. **기록**: 유형(출결/칭찬포인트/특이사항/과제제출) 드롭박스 선택 → 학생 선택 → 날짜(기본값 오늘, 수정 가능) → 내용 입력 후 저장. 목록은 최신순 표시, 학생별·유형별 필터 지원.

## 에러 처리 및 예외

- 반이 하나도 없는 상태로 학급 탭에 접근하면 설정 페이지로 안내 메시지와 함께 유도.
- 백업 파일 불러오기 시 파일 형식/버전을 검증하고, 실패 시 원인을 명확히 안내 (기존 데이터는 보존).
- 반 삭제 등 되돌릴 수 없는 작업은 확인 다이얼로그를 거친다.

## 테스트 방침

- 데이터 계층(Dexie CRUD 함수)에 대한 단위 테스트 작성 (Vitest).
- 백업 내보내기/불러오기 라운드트립 테스트 (내보낸 JSON을 다시 불러왔을 때 데이터 일치 확인).
- UI는 주요 플로우(진도 체크, 기록 추가, 자리배치 저장) 수동 확인.
