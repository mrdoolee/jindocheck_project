# 학급 진도 관리 — 사용자 매뉴얼

이 문서는 교사용 학급 진도/출결/기록 관리 앱의 사용법을 정리한 문서입니다. 앱 내 "사용자 매뉴얼" 버튼(왼쪽 메뉴 하단)에서 보이는 것은 이 문서의 요약본이고, 여기에는 스프레드시트 직접 편집 등 더 상세한 내용까지 담았습니다.

## 1. 기본 원칙

- **계정이 필요 없습니다.** 모든 데이터는 지금 이 브라우저(이 기기, 이 브라우저 앱)에만 저장됩니다.
- 다른 기기/다른 브라우저에서는 이 데이터가 보이지 않습니다. 기기를 바꾸거나 브라우저 데이터가 지워질 상황이 걱정된다면 **설정 > 백업**에서 JSON 백업을 받아두세요.
- Google 시트 동기화는 **선택 기능**입니다. 연결하지 않아도 앱의 모든 기능이 정상 동작합니다.

## 2. 시작하기

1. **설정 > 반 관리**에서 학급을 추가합니다.
2. **설정 > 명단 관리**에서 학급을 선택하고, 아래 형식으로 명단을 붙여넣습니다.
   ```
   번호,이름
   1,홍길동
   2,김철수
   ```
   (엑셀에서 번호/이름 두 열을 복사해서 붙여넣어도 탭으로 구분되어 인식됩니다.) 같은 탭에서 학생 번호/이름을 바로 수정하거나 삭제할 수 있습니다.
3. **설정 > 진도표 관리**에서 모든 학급이 공유하는 진도 항목(단원/차시)을 등록합니다.
4. 왼쪽 메뉴에서 학급 이름을 클릭하면 그 학급의 4개 탭으로 이동합니다.

## 3. 학급 페이지 4개 탭

| 탭 | 용도 |
|---|---|
| **진도체크** | 날짜를 선택해 그날 어떤 진도 항목을 완료했는지 체크합니다. |
| **출결확인** | 날짜를 선택해 학생별 출결 상태를 입력합니다. "이력보기"로 지난 날짜의 출결을 조회할 수 있습니다. |
| **누가기록** | 학생별 특이사항(누가기록)을 남깁니다. 전체 기록 보기와 학생별 조회, 날짜순/이름순 정렬을 지원합니다. |
| **자리배치표** | 행/열 크기를 조정하고, 학생을 드래그해서 자리를 배치합니다. 배치도를 JSON 파일로 불러올 수도 있습니다. |

학생 추가·삭제는 이 4개 탭이 아니라 **설정 > 명단 관리**에서만 합니다(의도된 설계입니다).

## 4. 백업

**설정 > 백업**에서:
- **내보내기**: 현재 모든 데이터(반/학생/진도표/진도기록/출결/누가기록/자리배치)를 JSON 파일 하나로 내려받습니다.
- **불러오기**: 내보낸 JSON 파일을 다시 앱에 불러와 복원합니다.

정기적으로(예: 학기 중 주 1회) 백업을 받아두는 것을 권장합니다. 특히 Google 시트 연결/해제를 실험해보기 전에는 반드시 먼저 백업하세요.

## 5. Google 시트 동기화 (선택 기능)

**설정 > Google 시트**에서 "구글 계정 연결하기"를 누르면:
- 구글 로그인 동의 화면으로 이동합니다.
- 승인하면 이 계정 전용의 새 스프레드시트가 자동으로 만들어지고("학급 진도 관리 동기화 (연결한 날짜)"라는 이름), 앱 데이터가 그 시트로 자동 동기화되기 시작합니다.
- 이후 앱을 열어둔 동안 변경 사항이 자동으로 동기화됩니다(로컬 변경 후 약 4초 뒤, 그리고 10초마다 반복 확인). "지금 동기화" 버튼으로 바로 동기화할 수도 있습니다.

**연결 해제**를 누르면 구글 계정 접근 권한 자체가 회수됩니다. 이후 다시 연결하면 **완전히 새로운 스프레드시트**가 만들어집니다 — 이전 시트는 구글 드라이브에 그대로 남아있지만 더 이상 이 앱과 연결되지 않습니다(구글 드라이브에서 직접 열어보거나 정리할 수 있습니다).

### 5.1 스프레드시트를 직접 열어봤을 때 — 탭/열 설명

시트에는 앱의 데이터 종류별로 탭이 하나씩 있습니다. 각 탭의 열(컬럼) 의미는 아래 표와 같습니다.

**중요**: `id`로 끝나는 열(`id`, `classId`, `studentId`, `curriculumItemId`)은 데이터끼리 서로 연결하기 위한 내부 참조 번호입니다. 이 값을 실수로 바꾸면 학생이 다른 반으로 옮겨지거나, 기록이 엉뚱한 학생 것으로 바뀌는 등의 문제가 생길 수 있습니다. **이 열들은 손대지 마세요.** 새 행을 시트에서 직접 추가하는 것도 권장하지 않습니다 — 새 반/학생/기록 추가는 항상 앱에서 하세요. 시트에서 안전하게 고쳐도 되는 것은 아래 표에 "직접 수정 가능"이라고 표시한 열들뿐입니다.

#### classes (반)
| 열 | 의미 | 직접 수정 |
|---|---|---|
| id | 내부 참조 번호 | ❌ |
| name | 반 이름 | ✅ |
| createdAt | 생성일시 | ❌ |
| order | 사이드바에 표시되는 순서 | ❌ (앱에서 드래그로 변경) |
| seatRows / seatCols | 자리배치표 행/열 개수 | ❌ (앱에서 변경) |
| updatedAt | 마지막 수정 시각(동기화 충돌 판단에 쓰임) | ❌ |

#### students (학생)
| 열 | 의미 | 직접 수정 |
|---|---|---|
| id | 내부 참조 번호 | ❌ |
| classId | 소속 반의 id | ❌ |
| number | 학생 번호 | ✅ |
| name | 학생 이름 | ✅ |
| role | 실장/부실장/도우미 등 역할 표시(출결확인 탭에 배지로 표시됨, 비워두면 표시 안 됨) | ✅ |
| seatRow / seatCol | 자리배치표 상 좌표 (비어있으면 미배치) | ❌ (앱에서 드래그로 변경) |
| updatedAt | 마지막 수정 시각 | ❌ |

#### curriculum (공통 진도표)
| 열 | 의미 | 직접 수정 |
|---|---|---|
| id | 내부 참조 번호 | ❌ |
| order | 표시 순서 | ❌ |
| unit | 단원명 | ✅ |
| lesson | 차시명 | ✅ |
| updatedAt | 마지막 수정 시각 | ❌ |

#### progress (진도 체크 기록)
| 열 | 의미 | 직접 수정 |
|---|---|---|
| id | 내부 참조 번호 | ❌ |
| classId | 어느 반의 기록인지 | ❌ |
| curriculumItemId | 어느 진도 항목인지 (curriculum 탭의 id) | ❌ |
| done | 완료 여부 (TRUE/FALSE) | ✅ (TRUE 또는 FALSE로만 입력) |
| date | 완료 처리한 날짜 | ✅ |
| updatedAt | 마지막 수정 시각 | ❌ |

#### attendance (출결)
| 열 | 의미 | 직접 수정 |
|---|---|---|
| id | 내부 참조 번호 | ❌ |
| classId | 어느 반인지 | ❌ |
| studentId | 어느 학생인지 (students 탭의 id) | ❌ |
| date | 출결 날짜 | ✅ |
| status | 출결 상태(출석/결석 등, 앱과 동일한 표기 사용) | ✅ |
| note | 비고 | ✅ |
| updatedAt | 마지막 수정 시각 | ❌ |

#### records (누가기록)
| 열 | 의미 | 직접 수정 |
|---|---|---|
| id | 내부 참조 번호 | ❌ |
| classId | 어느 반인지 | ❌ |
| studentId | 어느 학생인지 | ❌ |
| date | 기록 날짜 | ✅ |
| type | 기록 유형 | ✅ |
| content | 기록 내용 | ✅ |
| updatedAt | 마지막 수정 시각 | ❌ |

#### stickers
현재 앱 화면에는 이 데이터를 만드는 기능이 없어 항상 비어 있습니다(과거 기능의 흔적으로 스키마만 남아있음). 무시해도 됩니다.

### 5.2 동기화 관련 주의사항

- 앱과 시트를 동시에 수정하면, **더 나중에 수정된 쪽이 우선**됩니다(초 단위 타임스탬프 기준).
- 시트에서 행을 통째로 지우면 앱에서도 해당 데이터가 삭제됩니다(반대도 마찬가지) — 되돌릴 수 없으니 신중하게 지우세요.
- 동기화가 "실패" 상태로 계속 표시되면, 왼쪽 메뉴 하단의 "다시 시도" 버튼을 누르거나, 설정 > Google 시트에서 "지금 동기화"를 눌러보세요. 그래도 안 되면 연결을 해제했다가 다시 연결해보되, **연결 해제 전 반드시 백업을 받아두세요.**

## 6. 문의/문제 발생 시

이 앱은 별도 고객지원 채널이 없는 개인/소규모 개발 도구입니다. 문제가 생기면 우선 **설정 > 백업**으로 현재 상태를 저장해두고, 개발자에게 상황을 전달하세요.
